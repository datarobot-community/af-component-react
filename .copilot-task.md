# Backport hash-based frontend build triggers from recipe-datarobot-agent-application

Context:
- The recipe repo datarobot/recipe-datarobot-agent-application has a new infra module infra/infra/frontend_web.py that builds the frontend React app using a hash of source files as a Pulumi trigger, so the build only runs when frontend sources change.
- The af-component-react repo currently has template/infra/infra/{{ react_app_name }}.py.jinja, which generates the frontend build module (e.g. frontend_web.py) for apps. That template currently uses time.time() in the `triggers` argument, which forces a rebuild on every Pulumi run.
- We want af-component-react to be the source of truth and to backport the hash-based trigger behavior from the recipe into this component template.

Goal:
- Update template/infra/infra/{{ react_app_name }}.py.jinja so that:
  - It computes a SHA-256 hash of relevant frontend source/config files under project_dir / "{{ react_app_name }}".
  - Uses that hash as the Pulumi `triggers` value for the pulumi_command.local.Command that runs `npm install && npm run build`.
  - The build should only re-run when any of the relevant frontend files change.
- Keep the template structure and naming the same (react_app_name, _external_data.base.template_name, PROJECT_NAME).
- Do not change behavior unrelated to the build triggers unless necessary (keep npm install && npm run build, keep resource name format, module exports, etc.).

Details to replicate from recipe-datarobot-agent-application:
- From datarobot/recipe-datarobot-agent-application, look at infra/infra/frontend_web.py.
- It defines:
  - FRONTEND_SOURCE_GLOBS = [
      "src/**/*",
      "public/**/*",
      "package.json",
      "package-lock.json",
      "index.html",
      "tsconfig*.json",
      "vite.config.*",
      "tailwind.config.*",
      "postcss.config.*",
      "eslint.config.*",
      "components.json",
      ".prettierrc*",
      ".npmrc",
    ]
  - A helper _hash_frontend_sources(frontend_dir: Path) that walks those globs, deduplicates, sorts, and feeds relative paths and contents into a SHA-256.
  - In build_frontend(), it computes source_hash = _hash_frontend_sources(frontend_dir) and passes triggers=[source_hash] to pulumi_command.local.Command.

What to implement in af-component-react:
- In template/infra/infra/{{ react_app_name }}.py.jinja:
  - Import hashlib.
  - Define FRONTEND_SOURCE_GLOBS with the same list as above.
  - Define _hash_frontend_sources(frontend_dir: Path) exactly as in the recipe, but leave comments/godocs generic (reusable for any React app).
  - In build_frontend(), set:
      frontend_dir = project_dir / "{{ react_app_name }}"
      source_hash = _hash_frontend_sources(frontend_dir)
    and then pass triggers=[source_hash] instead of triggers=[str(time.time())].
  - Remove the unused import of time.

Acceptance criteria:
- template/infra/infra/{{ react_app_name }}.py.jinja produces modules that behave like the recipe’s infra/infra/frontend_web.py regarding when the build runs.
- The diff should be minimal and focused on:
  - Adding hashlib import and helper function + FRONTEND_SOURCE_GLOBS.
  - Switching triggers from time-based to hash-based.
  - Removing time import.
- All existing tests (if any) and template rendering should still work.

- Make sure formatting and style match the existing file (copyright header, blank lines, etc.).
